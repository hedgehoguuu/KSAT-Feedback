## 1. [P2] '바뀐 채점 보기' 를 눌러도 옛 점수가 남는다

위치: [`src/components/lms/GradeSheet.tsx:196`](https://github.com/hedgehoguuu/KSAT-Feedback/blob/3ae461f/src/components/lms/GradeSheet.tsx#L196)

정답표 수정으로 O 가 X 로 재채점된 뒤, 충돌 안내에서 새로 고침을 눌러도 기존 O 상태가 보존된다. 이후 저장하면
최신성 검사를 통과해 옛 점수를 다시 저장 · 공개할 수 있다.

수정 제안: 복구 버튼이 최신 데이터로 폼을 다시 생성하도록 하고, 입력값과 충돌 검사 기준을 함께 초기화한다.

### 반영 — `1480f71`

- 원인: `router.refresh()` 는 서버 컴포넌트만 다시 그리고 브라우저 쪽 `useState` · `useActionState` 는 남긴다
  (설치된 Next 16 의 `useRouter` 문서). 칸마다 매긴 것도, 거절될 때 받은 판(`saveState.base`)도 그대로였다.
  페이지의 `key` 는 응시 행의 `updated_at` 이라, 정답표 재채점처럼 응시 행이 안 바뀌는 변화에는 새로 붙지 않았다.
- `GradeSheet` 를 한 겹 감싸, 받은 판(정오 + 정답표, `gradingSnapshot`)을 `key` 로 채점표를 붙인다. 새로 고쳐 판이
  바뀌면 매긴 것 · 학생 답 · 총평 · 저장 결과가 같이 새 판에서 시작한다.
- 매기는 중에는 화면을 새로 고치지 않는 규칙(`dirty.ts`)은 그대로라 입력이 날아가지 않는다. 화면을 새로 고치는 곳은
  사진 읽기 감시(손질이 없을 때만)와 이 단추 둘뿐이다.
- 판이 같은 채로 새로 고쳐지면(고친 정답표를 도로 되돌린 경우) 새로 붙지 않는다. 그때도 견줄 판은 DB 가 거절하며
  준 지금 판이라, 옛 점수가 검사를 그냥 통과하지는 않는다.

확인: 타입 검사 · eslint · 빌드. 브라우저로 눌러 보지는 못했다 — 운영 DB 에 붙은 로컬 환경이 없다.

## 2. [P2] 다른 학생의 신청이 저장되지 않았는데 성공으로 안내된다

위치: [`supabase/migrations/0007_no_duplicate_apply.sql:43`](https://github.com/hedgehoguuu/KSAT-Feedback/blob/3ae461f/supabase/migrations/0007_no_duplicate_apply.sql#L43)

자리가 남은 반에 같은 학부모 번호로 다른 학생이 신청하면, DB 는 기존 신청 ID 를 반환한다. API 는 이를 신규 신청으로
취급해 성공 화면과 알림을 보내지만 새 학생은 신청 명단에 없다.

수정 제안: 신규 생성 · 동일 신청 재시도 · 다른 학생의 번호 중복을 구분해 반환하고, 신규 생성일 때만 알림을 보낸다.

### 반영 — `9415728` · DB 0019

- 앱이 새 신청의 id 를 미리 뽑아 넘긴다(`applyToClass`). `create_class_application` 은
  - 새로 만들면 넘긴 id 를,
  - 같은 번호 · 같은 이름의 살아 있는 신청이 있으면 그 신청의 id 를 돌려주고,
  - 같은 번호에 이름이 다르면 `PHONE_TAKEN` 으로 막는다.
- 돌려받은 id 가 넘긴 것과 같을 때만 새 신청이다. 알림은 그때만 간다. 겹친 재시도는 성공으로 답하되 알림을 다시
  보내지 않는다. `PHONE_TAKEN` 은 409 와 함께 이유를 말한다. 앞 학생의 이름은 알려 주지 않는다.
- 반환 방식으로 jsonb 대신 '넘긴 id 를 그대로 돌려주는가' 를 고른 이유: 시그니처와 반환 타입이 그대로라 0019 를
  먼저 돌려도 id 를 안 넘기는 옛 앱이 그대로 돈다. 대신 0019 없이 새 앱이 돌면 새 신청도 재시도로 보여 알림이 안
  가므로, `REQUIRED_MIGRATIONS` 에 더해 `/setup` 이 짚게 했다.

정한 것: **다른 학생은 받지 않고 막는다.** 한 번호에 한 자리는 0007(부모와 학생이 각각 신청해 자리가 헛되이 없어지는
것을 막음) · 0018(취소 복원 때 같은 연락처 검사)과 같은 규칙이다. 형제 · 자매는 그 번호로 연락할 때 사람이 받는다.
받기로 바꾸려면 0019 의 `PHONE_TAKEN` 자리에서 새 신청을 만들면 된다.

확인:

- 2026-09-19 00:12 (KST) 운영 DB 에 0019 적용 — `schema_migrations` 에 기록, 함수 본문 교체, `anon` ·
  `authenticated` 실행 권한 없음.
- 운영 DB 에서 늘 되돌리는 트랜잭션(`do` 블록 끝에서 예외) 안에 임시 반(정원 3)을 만들어 돌렸다. 새 신청은 넘긴 id,
  같은 학생 재시도는 처음 id, 다른 학생은 `PHONE_TAKEN` 이고 행이 안 생김, id 없이 부르는 옛 호출도 됨, 정원이 차면
  `CLASS_FULL`, 남은 행 3개. 끝난 뒤 임시 반이 남지 않은 것도 확인했다.

## 3. [P2] 풀이 사진이 빠진 PDF 도 발송 완료로 처리된다

위치: [`src/lib/lms/feedback.ts:64`](https://github.com/hedgehoguuu/KSAT-Feedback/blob/3ae461f/src/lib/lms/feedback.ts#L64)

사진으로만 답한 질문에서 이미지 다운로드가 실패하면 빈 이미지로 대체한다. 이후 답변 완료 검사를 통과해 풀이 없는
PDF 가 전달되고 학생의 수정도 잠긴다.

수정 제안: 실제 발송에서는 이미지 다운로드 · PDF 삽입 실패 시 완료 처리를 중단하고 재시도할 수 있게 한다.

### 반영 — `6508c14`

- `renderFeedbackPdf` 가 PDF 와 함께 싣지 못한 사진의 질문 번호(`missingImages`)를 돌려준다. 못 받아 온 사진(빈
  바이트)과 PDF 에 못 넣은 사진을 다 센다.
- `sendFeedback` 은 하나라도 있으면 파일 올리기 · `mark_feedback_ready` · 메일 전에 `IMAGE_MISSING` 으로 멈춘다.
  아무것도 바뀌지 않았으니 다시 누르면 된다. 튜터 화면은 사진을 못 실은 질문과 할 일(잠시 뒤 다시 · 안 되면 사진을
  떼고 다시 붙이기)을 짚는다.
- 미리 보기는 전처럼 그 자리에 글로 적어 보여 준다 — 무엇이 빠졌는지 보는 것도 미리 보기의 일이다.
- 사진이 있는 질문이면 글 답이 있어도 멈춘다. 튜터가 붙인 풀이가 빠진 채 나가는 것은 같은 문제다.

확인: `npm test` 에 네 줄을 더했다 — 깨진 사진과 빈 바이트는 빠진 것으로, 멀쩡한 1×1 PNG 와 사진 없는 질문은 아닌
것으로 센다. 저장소가 실제로 실패하는 경로는 `npm run test:db` 로 봐야 하는데 전용 테스트 DB 가 없어 못 돌렸다.
