01

매일 아침 1분

이 주소 하나만 열면 된다. 숫자 세 개를 보고 끝낸다. 관리자만 열리므로 먼저 /admin 에 로그인해 둔다 — 한 번 로그인하면 7일 유지된다. 로그인 없이 열면 "관리자만 볼 수 있어요" 만 뜬다.

매일 여기

ksat-feedback.vercel.app/api/health
"ready":true, "submissionCount":12, "pendingCount":0, "failureCount":0
submissionCount
지금까지 들어온 접수. 늘어나기만 하면 정상이다.
pendingCount
아직 처리 중인 접수. 30분 넘게 0이 아니면 손을 봐야 한다.
failureCount
해결 안 된 오류. 0이 아니면 아래 03번을 본다.
세 숫자가 정상이면 그날은 끝이다.

접수가 제대로 들어왔는지는 Notion을 보면 되고, 그건 피드백 쓰면서 어차피 보게 된다. 이 주소는 뭔가 조용히 망가졌는지만 확인하는 용도다.

화면으로 보고 싶으면 /setup 이 모든 항목을 ✓/✗ 로 보여준다. 다만 여기에는 접수 건수만 나오고 미처리·오류 숫자는 안 나온다. 매일 점검은 위의 /api/health 로 하는 게 맞다. 둘 다 같은 관리자 로그인으로 열린다. 스크립트로 부를 때는 03번의 명령처럼 x-worker-secret 헤더를 붙인다.

02

날짜별로 할 일

9/1 (월)
Supabase 깨우기

/setup 을 한 번 연다. 무료 플랜은 일주일 놀면 잠들어서, 안 깨우면 9/2 첫 접수가 느리거나 실패할 수 있다. 모든 항목이 초록인지도 같이 확인된다.

9/2 (화)
오픈 직후 첫 접수 한 건을 끝까지 본다

첫 접수가 들어오면 Notion에 줄이 생기고, PDF 링크가 붙고, 학생에게 메일이 갔는지 본다. 이 세 개가 한 건에서 다 되면 나머지도 된다. 안 되면 03번.

9/2 ~ 9/8
아침에 숫자 세 개, 그리고 용량

01번의 세 숫자를 보고, 접수가 하루 30건을 넘기 시작하면 04번의 저장 용량도 같이 본다. 그 아래로는 용량 걱정할 일이 없다.

9/9 (화)
9/2 접수분 회신 마감

학생에게 "7일 안에 보내드려요"라고 약속했고 완료 화면·메일에 날짜가 박혀 나갔다. 접수일마다 마감이 다르므로 Notion의 회신일 칸으로 관리한다.

9모 이후
Notion 토큰 정리

작업 중에 토큰이 대화 기록에 노출됐다. Notion 설정 → Connections 에서 그 연결을 삭제하거나 새로 발급한다. 급하진 않지만 잊기 쉬우니 회신 다 끝낸 날 같이 한다.

10/2 이후
사진은 저절로 지워진다

9/2 접수분 사진·PDF는 30일 뒤 자동 삭제된다. 접수 기록(몇 건 받았고 언제 회신했는지)은 남는다. 할 일 없음.

03

이상할 때

아래 명령의 SECRET 자리에는 Vercel → Settings → Environment Variables 의 WORKER_SECRET 값을 넣는다. 이 문서에는 일부러 적지 않았다.

증상왜할 일
pendingCount가
안 줄어든다		 제출 직후 후처리가 60초를 넘겨 잘렸다. 사진이 많을 때 생긴다. 기다리면 새벽 3시 크론이 되살린다. 급하면 그 접수번호로 재처리를 부른다.
Notion에
줄이 안 생겼다		 Notion API가 잠깐 막혔거나 후처리가 잘렸다. 재처리. 같은 접수를 다시 돌려도 줄이 두 개 생기지 않는다.
PDF 링크가
비어 있다		 사진 병합이 실패했거나 링크 유효기간이 지났다. 재처리하면 새 링크가 채워진다. 사진 원본은 그대로 있으니 잃는 건 없다.
확인 메일이
안 갔다		 Gmail 앱 비밀번호가 만료됐거나 하루 발송량을 넘겼다. 먼저 시험 메일을 한 통 보내본다 — /api/worker/status?mail=1
학생이 "접수가
안 돼요" 한다		 하루 상한 100건에 닿았거나 접수 스위치가 꺼졌다. /api/intake 를 열어 open 과 remainingToday 를 본다.
사이트가
느리다		 Supabase가 잠들었다가 깨는 중이다. 첫 요청만 느리다. 30초쯤 뒤 다시 해본다.

재처리 명령

curl -X POST -H "x-worker-secret: SECRET" \ "https://ksat-feedback.vercel.app/api/worker/process?receipt=F0902-013"

접수번호만 바꿔 쓴다. 이미 끝난 단계는 건너뛰므로 여러 번 불러도 안전하다. 무엇이 왜 막혔는지 원문으로 보려면 /api/worker/status 를 같은 헤더로 연다.

04

먼저 터지는 순서

한계에 닿는 순서대로다. 1번이 압도적으로 먼저 온다.

순위한계언제 닿나대응
1 저장 용량 1GB 접수 130~250건 Supabase 유료 전환, 또는 보관 기간을 30일에서 줄인다
2 튜터 3명의 시간 하루 10~20건? 실제로는 이게 먼저 온다. 하루 상한을 낮춘다
3 Gmail 500통/일 하루 500건 하루 상한이 100이라 닿을 일이 없다
4 Notion 초당 3회 동시 폭주 시 자동으로 기다렸다 다시 보낸다. 할 일 없음
용량은 이 주소로 본다
curl -H "x-worker-secret: SECRET" \ "https://ksat-feedback.vercel.app/api/worker/storage"

total.mb 가 700을 넘으면 슬슬 결정해야 한다. 접수 1건이 사진과 PDF 합쳐 4~8MB다. 하루 100건이 실제로 다 차면 이틀이면 바닥나므로, 상한 100은 용량을 지켜주지 못한다는 점을 기억할 것.

05

저절로 도는 것

아래는 신경 쓰지 않아도 된다. 무엇이 자동인지 알아야 괜히 손대지 않는다.

  • 밀린 접수 되살리기 — 후처리가 잘린 건을 다시 돌린다
  • 만료 사진 삭제 — 접수 30일 뒤 사진·PDF를 지운다. 접수 기록은 남는다
  • 주인 없는 사진 정리 — 사진만 올리고 그만둔 학생의 파일을 24시간 뒤 지운다
  • 하루 상한 초기화 — 한국 날짜가 바뀌면 저절로 0부터 다시 센다
06

바꿀 것은 코드가 아니다

운영 중 조정은 전부 Supabase → Table Editor → app_settings 한 줄에서 한다. 줄 오른쪽 끝 ⋯ → Edit row → 고치고 Save. 배포 없이 즉시 반영된다.

칸지금무슨 뜻
intake_openTRUEFALSE로 바꾸면 접수 전체 중단
daily_capacity100하루 몇 건까지. 비우면 상한 없음
disabled_subjects[]특정 과목만 닫기. 예: ["english","int_sci"]
closed_reason이번 회차 접수가 마감됐어요.접수를 껐을 때 학생에게 보이는 문구
daily_closed_reason오늘 접수는 다 찼어요.
내일 다시 열려요.		하루 상한에 닿았을 때 문구
capacityNULL통틀어 상한. 안 쓴다. 비워둘 것
건드리면 안 되는 것

id 는 반드시 1이어야 한다. 바뀌면 사이트가 이 줄을 못 찾는다. 그리고 이 표는 줄이 하나만 있어야 한다 — 새 줄을 추가하지 말 것.

과목 코드는 korean · math · english · int_sci · int_soc 다. 값을 바꿔도 이미 사이트를 열어둔 학생은 새로고침해야 보인다. 다만 제출할 때 서버가 한 번 더 확인하므로, 닫은 뒤 접수가 실제로 저장되지는 않는다.
