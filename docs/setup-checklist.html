코드를 GitHub에 올리기

오늘 · 5분

지금 코드는 이 맥북 안에만 있어요. Vercel은 GitHub을 보고 배포하기 때문에, 올리지 않으면 그다음이 전부 막혀요. 제가 대신 못 하는 이유는 이 컴퓨터에 GitHub 로그인 정보가 없어서예요.

  1. 터미널 열기
    ⌘ + 스페이스 → 터미널 입력 → 엔터. 검은 창이 뜨면 맞아요.
  2. GitHub 명령어 도구 설치하고 로그인
    아래를 한 줄씩 복사해서 붙여넣고 엔터. 두 번째 명령은 질문이 나와요 — GitHub.com → HTTPS → Y → Login with a web browser 를 고르고, 화면에 뜬 여덟 자리 코드를 복사해 브라우저에 붙여넣으면 끝이에요.
    brew install gh
gh auth login
  3. 코드 올리고 main에 합치기
    세 줄을 차례로 붙여넣으세요. 마지막 줄까지 하면 GitHub의 main에 앱이 들어가요.
    cd ~/Downloads/KSAT-Feedback
git push -u origin feat/apply-flow
gh pr create --fill --base main && gh pr merge --merge --delete-branch
  4. 빠뜨리기 쉬움
    github.com/hedgehoguuu/KSAT-Feedback 를 열어서 파일이 보이는지 확인
    src, supabase 폴더가 보이면 성공이에요. README만 있으면 아직 안 올라간 거예요. 여기서 막히면 이 시점에 저를 부르세요 — 로그인만 되어 있으면 나머지는 제가 할 수 있어요.

오늘 · 10분

학생이 올린 시험지 사진과 접수 내용이 저장되는 곳이에요. 무료 플랜으로 충분해요.

  1. supabase.com 에서 GitHub 계정으로 가입
    GitHub으로 로그인하면 비밀번호를 하나 덜 만들어도 돼요.
  2. 고르는 값 주의
    New project 만들기
    Name: ksat-feedback (아무거나 괜찮아요)
    Database Password: 자동 생성 버튼을 누르고, 그 값을 메모장에 저장하세요. 지금은 안 쓰지만 잃어버리면 재설정해야 해요.
    Region: Northeast Asia (Seoul) — 학생들이 한국에서 접속해요. 다른 지역을 고르면 사진 업로드가 눈에 띄게 느려지고, 나중에 바꾸려면 프로젝트를 새로 만들어야 해요.
  3. 2~3분 기다렸다가, 왼쪽 메뉴 SQL Editor 열기
    프로젝트가 다 만들어질 때까지 초록 점이 돌아요.
  4. 준비된 SQL 한 번 실행하기
    Finder에서 Downloads/KSAT-Feedback/supabase/migrations/0001_init.sql 파일을 텍스트편집기로 열어 전체 복사(⌘A ⌘C) → SQL Editor에 붙여넣고 Run. Success. No rows returned 가 나오면 정상이에요. 테이블·접수번호 발급기·저장소가 한 번에 만들어져요.
  5. Storage 메뉴에 exam-papers 가 생겼는지 확인
    이름 옆에 Public 표시가 없어야 맞아요. 공개로 되어 있으면 남의 시험지를 아무나 볼 수 있게 돼요.
  6. 비밀 값
    Settings(톱니) → API 에서 두 값 복사해두기
    Project URL — https://…….supabase.co 로 끝나야 해요. 뒤에 /rest/v1/ 가 붙어 있으면 바로 아래 RESTful endpoint 칸을 복사한 거예요. 그걸 넣으면 접속은 되는 것처럼 보이다가 사진 업로드와 접수 저장이 전부 실패해요. 끝의 슬래시도 지우세요.
    service_role 키 — 눈 아이콘을 눌러야 보여요. 이 값은 DB 전체를 여는 마스터 키예요. 카톡·노션·문서에 붙여넣지 말고, 다음 단계에서 Vercel에만 넣으세요.
    (anon 키는 지금 안 써요.)
03

Vercel에 올려서 링크 만들기

오늘 · 10분

여기서 나오는 주소가 학생에게 뿌릴 링크예요. 8/29 회의 시연도 이 링크로 하면 돼요.

  1. vercel.com 에서 Continue with GitHub 로 가입
    개인 용도는 무료(Hobby)로 충분해요.
  2. Add New… → Project → KSAT-Feedback Import
    Framework는 Next.js로 자동으로 잡혀요. Root Directory는 건드리지 마세요. 목록에 레포가 안 보이면 Adjust GitHub App Permissions에서 이 저장소에 접근 권한을 주세요.
  3. 여기서 제일 많이 틀려요
    Deploy 누르기 전에 Environment Variables 두 개 넣기
    왼쪽 Key 칸에는 이름, 오른쪽 Value 칸에는 값이에요. 자리가 바뀌면 “name contains invalid characters” 오류가 나요 — 이름에는 영문·숫자·밑줄만 들어갈 수 있거든요.
    이름을 한 글자도 다르게 쓰면 안 돼요. 특히 앞에 NEXT_PUBLIC_를 붙이면 키가 브라우저로 새어 나가요.
    여러 줄을 한꺼번에 붙여넣으면 Vercel이 알아서 여러 개로 쪼개요(“7 Detected” 같은 표시). 우리가 쓰는 건 아래 두 개뿐이니, 나머지 줄은 오른쪽 − 버튼으로 지우세요. 
    SUPABASE_URL               = 2단계에서 복사한 Project URL
SUPABASE_SERVICE_ROLE_KEY  = 2단계에서 복사한 service_role 키
    이 화면에는 환경(Production/Preview/Development) 선택이 없어요 — 그게 정상이에요. 처음 Import 할 때 넣은 변수는 자동으로 세 환경 모두에 적용돼요. 환경별 선택은 배포가 끝난 뒤 Settings → Environment Variables 에서만 나와요.
    값 칸 옆 노란 자물쇠(Sensitive)는 service_role 키에 켜두면 좋아요. 켜면 나중에 Vercel에서 값을 다시 볼 수 없지만, 필요하면 Supabase에서 다시 복사하면 돼요.
  4. Deploy 누르고 1~2분 기다리기
    끝나면 ksat-feedback-…….vercel.app 같은 주소가 나와요. 그게 링크예요.
  5. Settings → Functions → Region을 Seoul (icn1) 으로 바꾸고 다시 배포
    기본값은 미국이에요. 서울로 바꾸면 사진 올릴 때 왕복 시간이 줄어요. 바꾼 뒤 Deployments 탭에서 맨 위 배포의 ⋯ → Redeploy.
  6. Analytics 탭에서 Web Analytics 켜기
    Vercel 프로젝트 상단 Analytics 탭 → Enable. 코드는 이미 붙여뒀지만, 여기서 켜지 않으면 숫자가 하나도 안 쌓여요. 켠 뒤부터의 방문만 집계되니 접수 오픈 전에 켜두셔야 해요.
    단계마다 주소가 달라서 별도 설정 없이 퍼널이 그려집니다 — 랜딩 몇 명 → 시험 선택 몇 명 → 업로드 몇 명 → 제출 완료 몇 명.
  7. 주소 뒤에 /setup 을 붙여서 열기
    제가 만들어 둔 점검 화면이에요. 환경변수·DB 연결·테이블·저장소가 전부 ✓면 준비 끝이에요. ✗가 있으면 그 칸에 뭘 해야 하는지 한국어로 적혀 있어요.

안전 수칙

절대 하면 안 되는 것

  • service_role 키를 카톡·노션·문서·깃허브에 붙여넣기. 그 키 하나로 학생 데이터 전체를 읽고 지울 수 있어요. Vercel 환경변수 칸에만 넣으세요.
  • 환경변수 이름 앞에 NEXT_PUBLIC_ 붙이기. 그 접두사가 붙으면 브라우저로 그대로 나가요.
  • Supabase 버킷을 Public으로 바꾸기. 남의 시험지를 주소만 알면 누구나 보게 돼요.
  • 학생 이메일이 담긴 Notion 데이터베이스를 링크 공개로 돌리기. 사람을 개별 초대하세요.

이건 제가 이미 해뒀어요 — 안 하셔도 돼요

  • 접수 데이터에 RLS를 켜서, 익명 접속자는 남의 접수를 읽지도 고치지도 못해요.
  • 시험지 버킷은 비공개이고, 업로드는 서버가 그때그때 발급한 일회용 주소로만 돼요.
  • 마스터 키는 서버에서만 쓰이도록 코드에 잠금(server-only)이 걸려 있어요.
  • 제출은 멱등키로 묶여서, 학생이 여러 번 눌러도 접수는 1건이에요.
  • 접수 1건 + 과목 + 사진 목록이 한 번에 다 저장되거나, 아예 안 되거나 둘 중 하나예요 (중간에 깨진 접수가 안 생겨요).
  • 접수 on/off·상한·과목별 차단은 Supabase 표 한 줄만 고치면 배포 없이 바로 먹혀요.
  • 360px 좁은 화면, 브라우저 뒤로가기, 새로고침, 통신 끊김 후 이어하기까지 확인해뒀어요.

아직 없는 것 (알고는 계셔야 해요)

  • 시험지 PDF 합치기 · Notion 자동 등록 — 8/30 작업분이에요. 그전까지는 Supabase에서 직접 봐야 해요.
  • 접수 확인 메일이 아직 안 나가요. 학생은 완료 화면의 접수번호만 봐요.
  • 스팸 방지가 없어요. 링크가 크게 퍼지면 장난 접수가 들어올 수 있어요. 상한을 걸어두는 걸 권해요.
  • Supabase 무료 플랜은 일주일 내내 아무 접속이 없으면 프로젝트가 잠들어요. 9/1에 한 번 링크를 열어서 깨워두세요.
막히면 어느 단계 몇 번에서 무슨 화면이 떴는지만 알려주세요. 화면 캡처면 더 좋고요.
