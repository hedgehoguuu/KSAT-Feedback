관찰반 모집 설계서

9모 시험지 피드백을 받은 학생에게 유료 수업을 처음 알리는 페이지. 파는 것은 해설이 아니라 80분 동안 옆에서 본 기록이고, 페이지가 할 일은 그 사실을 한 화면 안에 이해시킨 다음 지금 열려 있는 반으로 데려가는 것이다.

초안 · 검토 대기 대상 화면 /class 선행 문서 class-180.html 모수 9모 국어 신청자 20명
00 — 한 장 요약

세 가지를 순서대로 말하는 한 페이지

학생이 스크롤하는 순서가 곧 설득의 순서다. 무엇을 하는 수업인지 → 누구와 하는 수업인지 → 지금 어느 반이 열려 있는지. 이 셋 말고는 넣지 않는다.

순서학생이 갖는 질문페이지가 답하는 방식출처
①이거 무슨 수업인데?180분 자 + 실제 관찰 기록지 4줄고정
②나한테 맞나?받는 학생 / 받지 않는 학생 대조고정
③언제, 얼마, 누구한테?개설 클래스 카드관리자

고정 은 배포로만 바뀌는 내용, 관리자 는 배포 없이 /admin 에서 바꾸는 값이다. 이 구분이 이 문서 전체에서 같은 색으로 따라다닌다.

성공 기준

  • 2주 안에 3인 반 두 개(6명)를 채운다. 20명 중 6명이면 30%다.
  • 페이지 도달 → 신청 폼 제출 15% 이상. 도달이 20명뿐이라 비율보다 절대수를 본다.
  • 신청자 중 “관찰이 불편하다”는 이유의 이탈 0명. 걸러내는 것도 이 페이지의 일이다.

하지 않는 것

  • 온라인 결제 — 계좌이체 안내로 대신한다. 6명 받자고 PG를 붙이지 않는다.
  • 학생 로그인·마이페이지 — 신청은 폼 한 번으로 끝난다.
  • 출결·성적 관리 — 수업 운영 도구는 이 페이지의 범위가 아니다.
  • 국어 외 과목 — 수학은 100분이라 180분 구조에 들어가지 않는다(class-180 §Q6).

02 — 섹션 ①

우리는 이런 구조의 수업을 설계했어요

설명하지 말고 보여준다. 이 구간의 주장은 하나다 — 사진으로 남은 시험지에는 순서와 시간이 없다. 그래서 시험을 치는 중에 옆에 앉는다.

80분 실전 풀이 — 학생은 시험을 치고, 튜터는 개입 없이 기록한다
10분휴식
90분 피드백 — 총평 10 · 시간과 병목 20 · 문항 해설 30 · 실전 개념 20 · 개인 교정 10
00:0001:2001:30 → 03:00

이 구간에 들어가는 것

  1. 180분 자 — 위 그림 그대로. 80:10:90 비율을 눈금으로 지킨다.
  2. 관찰 기록지 네 줄 — 실제 수업에서 나온 문장. 이 페이지에서 가장 설득력 있는 자산이므로 가공하지 않는다.
  3. 받아가는 것 세 가지 — 빨간펜 필기본 · 시간 기록표 · 다음 회차까지 고칠 행동 한 줄.
  4. 9모 연결 한 줄 — “보내주신 9월 시험지에서 본 것을, 이번엔 시험 중에 봅니다.” 이 페이지를 받는 20명은 이미 우리 피드백을 읽은 사람들이다.
넣지 않는다. 커리큘럼 표, 주차별 진도, 교재 목록. 그것이 붙는 순간 이 수업은 학원 시간표와 구별되지 않고, 우리가 파는 것이 관찰이 아니라 진도라고 말하게 된다.
03 — 섹션 ②

우리는 이런 학생을 원해요

거르는 문장을 페이지에 그대로 쓴다. 3인 정원이라 한 명을 잘못 받으면 세 명의 수업이 흔들리고, “관찰당하는 게 불편한 학생”은 우리가 가장 잘 못 가르치는 학생이다.

이런 학생과 합니다
  • 다른 사람이 푸는 걸 옆에서 보면 자극을 받는 학생
  • 아는데 시간이 모자라서 틀리는 학생
  • 자기 습관을 지적받을 준비가 된 학생
  • 혼자 풀 때와 시험장에서의 자기가 다르다고 느끼는 학생
이런 학생은 다른 곳이 낫습니다
  • 개념이 아직 안 잡힌 학생 — 80분을 채우지 못하면 관찰할 것이 없습니다
  • 해설만 빠르게 듣고 싶은 학생 — 해설은 90분 중 30분뿐입니다
  • 옆에서 지켜보는 것이 불편한 학생
“학생의 행동을 관찰해서, 나아지게 하는 수업.”

페이지에서 이 문장은 한 번만, 이 자리에서만 쓴다. 반복하면 표어가 되고 표어는 읽히지 않는다.

04 — 섹션 ③ · 데이터

현재 개설되어 있는 클래스

가격·정원·요일·튜터는 아직 정해지지 않았고, 정해진 뒤에도 계속 바뀐다. 그래서 이 구간만 DB에서 읽고 /admin 에서 고친다. 나머지 페이지는 코드에 박아 둔다 — 바뀌지 않는 것을 편집 가능하게 만드는 것이 관리 비용이다.

표 하나를 더한다

-- supabase/migrations/0005_classes.sql create table if not exists classes ( id uuid primary key default gen_random_uuid(), slug text unique not null, -- korean-thu-19 subject_code text not null default 'korean', title text not null, tutor_name text not null, tutor_credential text, schedule_text text not null, starts_on date, sessions int, location text, capacity int not null default 3, price int not null, -- 원, 총액 price_note text, recommend text, detail text, status text not null default 'draft', -- draft|open|closed sort_order int not null default 0, updated_at timestamptz not null default now() ); -- 익명 정책을 만들지 않는다 = 브라우저에서 직접 못 읽는다. -- 페이지는 서버 컴포넌트가 service_role 로 읽어서 그린다 (app_settings·exam-papers 와 같은 방침). alter table classes enable row level security;
기존 규칙 그대로. SUPABASE_SERVICE_ROLE_KEY 는 서버에서만 쓰고 NEXT_PUBLIC_ 접두사를 붙이지 않는다. 클래스 목록은 /class 서버 컴포넌트가 supabaseAdmin() 로 읽고 dynamic = 'force-dynamic' 으로 캐시하지 않는다 — 관리자에서 고친 값이 바로 보여야 한다.

빈 상태와 마감 상태

  • 모집중인 반이 없을 때 — “지금은 열린 반이 없어요. 다음 반이 열리면 알려드릴게요” + 알림 신청(이메일 한 칸). 페이지를 빈 채로 두지 않는다.
  • 정원이 찼을 때 — 카드는 남기고 버튼만 “대기 신청”으로. 찬 반이 보이는 것 자체가 근거다.
  • 초안(draft) — 페이지에 나오지 않는다. /class?preview=<토큰> 로만 확인한다.
05 — 관리자

배포 없이 고치는 화면

지금 /setup 이 하는 일(설치 점검)에 편집이 더해진다. 화면 두 개면 충분하다.

경로하는 일비고
/admin클래스 목록 — 상태·정렬·신청 수를 한 줄씩새 반 만들기, 복제
/admin/class/[slug]위 표의 필드를 그대로 담은 편집 폼저장 즉시 /class 반영
/admin/applications신청자 목록 — 이름·연락처·희망 반·신청 시각표 복사(CSV)
/admin/login비밀번호 한 칸아래 참조

잠금

  • 환경변수 ADMIN_PASSWORD 하나. 맞으면 httpOnly · Secure · SameSite=Lax 쿠키를 굽고, 만료는 7일.
  • /admin 아래 모든 경로와 쓰기 API를 같은 검사로 막는다. 화면만 막고 API가 열려 있으면 잠근 것이 아니다.
  • 쓰기는 전부 서버에서 supabaseAdmin() 으로. 브라우저는 Supabase 를 직접 만지지 않는다.
  • 같이 처리한다 — 지금 /setup 은 아무나 열 수 있고 접수 건수·환경변수 상태가 보인다. 같은 잠금 뒤로 옮긴다.
구현 전에 확인. 이 저장소는 Next 16 이고 훈련 데이터의 Next 와 다르다(AGENTS.md). 미들웨어·쿠키·서버 액션 API 는 node_modules/next/dist/docs/ 를 읽고 쓴다. 이 문서는 “무엇을 막는가”까지만 정하고 호출 형태는 정하지 않는다.

07 — 순서

만드는 순서

M1 만으로도 20명에게 보낼 수 있다. 값이 안 정해졌다고 페이지를 미루지 않는다.

  • M1 · 반나절 — /class 정적 페이지. 섹션 ①②까지, 클래스는 코드에 박아 둔 한 개. CTA 는 문의 메일.
  • M2 · 하루 — classes 표 + 서버 렌더. 빈 상태·마감 상태 포함.
  • M3 · 하루 — /admin 잠금과 편집 폼. /setup 도 같이 잠근다.
  • M4 · 하루 — 신청 폼 · 알림 메일 · 신청자 목록 · 90일 삭제.
